# SynoDLNA

UPnP/DLNA **клиент** к внешнему DLNA-серверу (например, Synology NAS с включённым Media Server).

> **Не путать с `Modules/DLNA`.** `DLNA` — это отдельный модуль-раздача: торрент-клиент и
> файловый медиасервер самого Lampac, маршруты `/dlna/*`. `SynoDLNA` не раздаёт ничего сам —
> он ходит по UPnP `ContentDirectory` на **чужой** DLNA-сервер (адрес в `init.conf`) и
> отдаёт клиенту Lampa список папок/файлов и подписанные ссылки на медиа.

Модуль — перенос `test_plugins/synology_dlna.js` на сервер: раньше клиент сам делал SOAP-запрос
`Browse` напрямую на NAS через отдельный неаутентифицированный nginx-прокси на порту `:8088`.
Теперь `Browse` выполняет сервер (server→server, CORS не проблема), а медиа отдаётся через
`/proxy/...` либо, для LAN-клиентов, прямой ссылкой на NAS.

## Модель доступа

- Аутентификация — **только явные токены из `SynoDLNA.users` в `init.conf`**. Модуль не
  использует `accsdb`, `account_email`, `uid`, `group` и никак не завязан на общую систему
  пользователей Lampac.
- Токен передаётся заголовком `X-Syno-Token` (предпочтительно) или query-параметром
  `syno_token` (учтите: попадёт в логи веб-сервера/access-логи).
- Сравнение токена — constant-time (`SHA256` + `CryptographicOperations.FixedTimeEquals`),
  независимо от длины строки.
- Клиенты из локальной сети (`requestInfo.IsLocalIp`) могут быть допущены без токена флагом
  `allowLocalWithoutToken` (по умолчанию `true`).
- Отзыв доступа — удалить (или выключить `enable: false`) соответствующую запись в `users`.
- Клиент никогда не передаёт серверу ни адрес NAS, ни произвольный URL — всё резолвится на
  сервере из `SynoDLNA.url` и присланного `objectId`.

### Если на сервере включен `accsdb`

`accsdb` — отдельный, независимый слой, который отрабатывает **до** контроллера
`SynoDLNA`, в middleware (`Core/Middlewares/Accsdb.cs`). При `accsdb.enable = true` запрос,
не попавший под `whitepattern` (по умолчанию не задан) и не содержащий `account_email`+`uid`
зарегистрированного устройства (или `token`), будет отбит самим middleware ещё до того, как
до него дойдёт проверка `X-Syno-Token`. Поэтому запрос к `/syno_dlna/*` должен одновременно
удовлетворять **обоим** слоям: пройти `accsdb` (штатная регистрация устройства/`whitepattern`)
и предъявить токен модуля. Плагин добавляет `account_email`/`uid` в запросы автоматически
(см. `account()` в `plugin.js`) именно для того, чтобы пройти слой `accsdb` — это не меняет и
не расширяет авторизацию самого модуля, которая остаётся только по `X-Syno-Token`.

Сгенерировать токен:

```bash
openssl rand -hex 32
```

## Конфигурация (`init.conf`, секция `SynoDLNA`)

| Поле | Тип | По умолчанию | Назначение |
|---|---|---|---|
| `enable` | bool | `false` | Включает модуль. |
| `url` | string | — | Базовый адрес DLNA-сервера, например `http://10.1.1.100:50001`. |
| `rootObjectId` | string | `"0"` | ObjectID корневой папки Browse. |
| `subtitles` | bool | `true` | Подбирать внешние субтитры (из DIDL и угадыванием соседних файлов). |
| `directLocalIp` | bool | `true` | Для LAN-клиентов отдавать прямую ссылку на NAS вместо `/proxy`. Касается только видео и картинок (их грузят теги `video`/`img`, которым CORS не нужен). Субтитры всегда идут через `/proxy`: Лампа качает их через XHR, а DLNA-сервер Synology заголовков CORS не отдаёт. |
| `allowLocalWithoutToken` | bool | `true` | Разрешить LAN-клиентам доступ без токена. |
| `timeoutSeconds` | int | `10` | Таймаут SOAP-запроса к NAS. |
| `cacheMinutes` | int | `5` | TTL кеша распарсенного ответа Browse (сырые URL, без прокси-ссылок). |
| `users` | array | `[]` | Список `{ name, token, enable }`. |

`limit_map` для `^/syno_dlna/` подставляется автоматически в `WAF.limit_map`.

## Маршруты

| Маршрут | Auth | Назначение |
|---|---|---|
| `GET /syno_dlna.js`, `GET /syno_dlna/js/{token}` | нет | Раздача `plugin.js`. Код одинаков для всех и не содержит токенов — анонимный доступ и `Staticache` безопасны. |
| `GET /syno_dlna/ping` | да | Проверка токена, `{ ok: true }` или `401`. |
| `GET /syno_dlna/browse?id=&flag=` | да | Листинг: `id` (по умолчанию `rootObjectId`), `flag` (по умолчанию `BrowseDirectChildren`). Ответ `{ folders: [...], files: [...] }`. |
| `GET /syno_dlna/subtitles?id=` | да | Субтитры для элемента (сначала DIDL/`BrowseMetadata`, затем угадывание соседних файлов). |

Ошибки: `403 { error: "disabled" }` — модуль выключен; `401 { error: "unauthorized" }` — токен
не прошёл проверку; `502 { error: "upstream" }` — NAS не ответил или прислал неразбираемый XML;
`503 { error: "not_configured" }` — `url` не задан или не парсится.

## Установка

Модуль пользовательский и живёт в `mods/` — встроенные файлы Lampac он не трогает, поэтому
обновления Lampac его не задевают и не конфликтуют с ним.

1. Положите папку в `mods/SynoDLNA` рядом с исполняемым файлом Lampac.
2. Убедитесь, что `BaseModule.LoadModules` не пуст (по умолчанию `[".*"]`) и `SynoDLNA` не
   указан в `BaseModule.SkipModules` — иначе компиляция папки будет пропущена.
3. Перезапустите Lampac. В консоли старта должно появиться `compilation SynoDLNA`.

В Docker подключается томом:

```yaml
services:
  lampac:
    volumes:
      - ./lampac-docker/mods/SynoDLNA:/lampac/mods/SynoDLNA
```

`manifest.json` стоит с `"dynamic": true`: Roslyn следит за `.cs`-файлами модуля и
пересобирает сборку на лету, без перезапуска.

> **Ошибка компиляции роняет старт целиком.** Если Roslyn не сможет собрать модуль, Lampac не
> поднимется (`error compilation mods/SynoDLNA` → исключение в `Core/Startup.cs`). Поэтому в
> папке оставлен `SynoDLNA.csproj` — загрузчик его игнорирует, но
> `dotnet build mods/SynoDLNA/SynoDLNA.csproj` позволяет поймать ошибки до деплоя.
> Папки `bin/` и `obj/`, которые появятся после такой сборки, убирать не нужно: Roslyn
> берёт только файлы из `tree` манифеста (`CSharpEval.cs:133`), а `*.dll` подхватываются
> лишь из корня `mods/`, не из подпапок модуля.

## Подключение плагина в Lampa

Добавьте запись в `LampaWeb.customPlugins` в `init.conf`:

```json
{
  "LampaWeb": {
    "customPlugins": [
      {
        "url": "{localhost}/syno_dlna.js",
        "status": 1,
        "name": "Synology DLNA",
        "author": "and7rey + maks56893"
      }
    ]
  }
}
```

Token-маршрут accsdb (`/syno_dlna/js/{token}`) намеренно **не** используется: токен SynoDLNA
не имеет отношения к токену accsdb, и смешивать их нельзя. Записи `customPlugins` token-маршрут
и не получают — для этого модуля это ровно то, что нужно.

Токен доступа пользователь вводит один раз в настройках клиента («Токен доступа», ввод текста —
работает и с пульта ТВ через экранную клавиатуру Лампы) и может сразу проверить кнопкой
«Проверить токен».

## Кеширование и проксирование

Кешируются **только распарсенные элементы с сырыми (NAS) URL**, ключ
`syno_dlna:browse:{objectId}:{flag}` / `syno_dlna:meta:{id}`, TTL `cacheMinutes`. Подстановка
публичной ссылки (`/proxy/...` через `HostStreamProxy` либо прямая ссылка на NAS для LAN)
выполняется **на каждый запрос заново, после чтения из кеша** — проксированные ссылки могут
быть привязаны к IP клиента (`serverproxy.verifyip`) и иметь ограниченный срок жизни, поэтому
закешированная ссылка, отданная другому клиенту, работать не будет.

## Безопасность XML/SOAP

- `objectId`, попадающий в SOAP-конверт, экранируется (`SecurityElement.Escape`) — в
  оригинальном JS-плагине он подставлялся без экранирования (XML-инъекция).
- Весь XML (SOAP-конверт и вложенный DIDL-Lite) разбирается только через `XmlReader` с
  `DtdProcessing.Prohibit` и `XmlResolver = null` (защита от XXE).
- Прежде чем сервер сделает GET по URL кандидата субтитров (угадывание по расширению файла),
  проверяется совпадение хоста этого URL с хостом `SynoDLNA.url` — DIDL-ответ приходит от NAS
  и не считается доверенным настолько, чтобы сервер ходил по нему куда угодно.

## Миграция со старого плагина (`customPlugins` + nginx `:8088`)

### Нужен ли ещё внешний CORS-прокси

Нет. Прокси существовал ровно по одной причине: браузер не давал плагину обратиться к NAS
напрямую. После переноса на сервер ни одного такого обращения не остаётся:

| Что раньше шло через прокси | Теперь |
|---|---|
| SOAP `Browse` (`ContentDirectory/control`) | Делает сервер (server→server). CORS не применяется. |
| Перебор субтитров (`.srt`/`.ass`/`.vtt`) | Делает сервер. |
| Загрузка субтитров плеером (XHR) | Через `/proxy` на домене Lampac — тот же origin. |
| Видео и картинки | Теги `video`/`img`, которым CORS не нужен: работают и через `/proxy`, и напрямую. |

Отдельно про `directLocalIp`: он отдаёт LAN-клиентам прямую ссылку на NAS **только для видео и
картинок**. Субтитры всегда идут через `/proxy`, потому что их Лампа качает через XHR, а
Synology заголовков CORS не отдаёт. Так что даже при `directLocalIp: true` внешний прокси не нужен.

### Порядок действий

Порядок важен: сначала поднимаем новое и убеждаемся, что оно работает, и только потом убираем
старое. Не удаляйте `:8088`, пока не пройдёт проверка из шага 5.

**1. Сгенерируйте токены** — по одному на человека или устройство, чтобы доступ можно было
отзывать по отдельности:

```bash
openssl rand -hex 32
```

```powershell
# без openssl
-join ((1..32) | ForEach-Object { '{0:x2}' -f (Get-Random -Max 256) })
```

**2. Положите модуль в `mods/SynoDLNA`** (см. раздел «Установка» выше; в Docker — том
`./lampac-docker/mods/SynoDLNA:/lampac/mods/SynoDLNA`).

**3. Правки в `init.conf`** — старую запись в `customPlugins` заменяем на новую, секцию
`SynoDLNA` добавляем:

```json
{
  "SynoDLNA": {
    "enable": true,
    "url": "http://10.1.1.100:50001",
    "directLocalIp": true,
    "allowLocalWithoutToken": true,
    "subtitles": true,
    "users": [
      { "name": "tv-room", "token": "ВАШ_ТОКЕН", "enable": true }
    ]
  },
  "LampaWeb": {
    "customPlugins": [
      {
        "url": "{localhost}/syno_dlna.js",
        "status": 1,
        "name": "Synology DLNA",
        "author": "and7rey + maks56893"
      }
    ]
  }
}
```

Старая запись, которую нужно **удалить** из `customPlugins`:

```json
{ "url": "{localhost}/syno_dlna_fork.js", "status": 1, "name": "Synology DLNA Fork" }
```

И убедитесь, что `SynoDLNA` не попал в `BaseModule.SkipModules`, а `LoadModules` не пуст.

**4. Перезапустите Lampac** и проверьте, что модуль собрался: в консоли старта должна быть
строка `compilation SynoDLNA`.

**5. Проверьте сервер до того, как трогать клиент:**

```bash
# плагин отдаётся
curl -sS -o /dev/null -w '%{http_code}\n' https://ваш.домен/syno_dlna.js

# токен принят
curl -sS -H 'X-Syno-Token: ВАШ_ТОКЕН' https://ваш.домен/syno_dlna/ping
# ожидаем: {"ok":true}

# без токена — отказ
curl -sS -o /dev/null -w '%{http_code}\n' https://ваш.домен/syno_dlna/ping
# ожидаем: 401 (или 200, если запрос пришёл с LAN и allowLocalWithoutToken=true)

# каталог читается
curl -sS -H 'X-Syno-Token: ВАШ_ТОКЕН' 'https://ваш.домен/syno_dlna/browse?id=0'
```

Если включён `accsdb`, к каждому из этих запросов добавьте `?account_email=...&uid=...` —
иначе ответ отдаст middleware accsdb, а не модуль.

**6. На клиенте:**

- удалите старый плагин в Лампе: «Расширения» → запись `Synology DLNA Fork` → удалить;
- перезагрузите Лампу — новый плагин подключится сам, по записи в `customPlugins`;
- откройте «Настройки» → `SynoDLNA`, введите токен в поле «Токен доступа» и нажмите
  «Проверить токен» — должно появиться подтверждение;
- откройте пункт `SynoDLNA` в меню, зайдите в папку, **запустите видео с внешними субтитрами**
  и убедитесь, что субтитры подхватились. Это главная проверка: именно субтитры раньше
  требовали CORS-прокси.

Старые клиентские настройки `synology_dlna_server` и `synology_dlna_proxy` в `Lampa.Storage`
новый плагин не читает. Их можно оставить, но чище удалить через «Настройки» → очистка, либо
в консоли браузера:

```js
Lampa.Storage.set('synology_dlna_server', '');
Lampa.Storage.set('synology_dlna_proxy', '');
```

**7. Удалите старый файл плагина** из `wwwroot` (например `wwwroot/syno_dlna_fork.js`).

**8. Только теперь убирайте nginx.** Найдите блок:

```bash
grep -rn 'listen 8088' /etc/nginx/
```

Удалите весь `server { listen 8088; ... }` (или файл целиком, если в нём только он), затем:

```bash
nginx -t && nginx -s reload
```

Если nginx запущен в Docker — уберите ещё и публикацию порта в `docker-compose.yaml`
(`"8088:8088"`) и пересоздайте контейнер: `docker compose up -d`. Без этого порт останется
открытым, даже если конфиг внутри контейнера уже пуст.

**9. Проверьте, что порт закрыт:**

```bash
curl -sS -m 5 -o /dev/null -w '%{http_code}\n' http://ваш.домен:8088/ || echo 'порт закрыт'
ss -lntp | grep 8088 || echo 'никто не слушает 8088'
```

### Если хотите подстраховаться перед удалением

Перед шагом 8 подержите новую схему несколько дней и посмотрите, обращается ли кто-нибудь ещё
к старому прокси:

```bash
grep -c ' 8088 ' /var/log/nginx/access.log
```

Пустой результат означает, что устройств на старом пути не осталось.

### Откат

Сохраните удаляемый `server{}` в файл перед удалением. Возврат: положить конфиг обратно,
`nginx -t && nginx -s reload`, в `init.conf` вернуть в `customPlugins` старую запись вместо
новой, при необходимости выставить `SynoDLNA.enable: false` и перезапустить Lampac.
Исходный плагин (`test_plugins/synology_dlna.js`) намеренно оставлен как референс.

## Вне объёма модуля

- SSDP-автопоиск DLNA-устройств не реализован — адрес сервера задаётся вручную в `init.conf`.
